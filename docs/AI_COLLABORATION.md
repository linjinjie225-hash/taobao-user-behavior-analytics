# AI 协作说明

本项目把 AI 作为候选方案生成器和审阅工具，而不是数据来源或结论签署者。模型输出必须经过代码执行、来源核对和人工判断后，才能进入公开材料。

## DeepSeek：业务问题与候选指标

DeepSeek 用于发散业务问题和指标候选，例如活跃时段、行为阶段覆盖、短周期留存与类目差异。候选项只决定“值得检查什么”，不直接决定指标定义，也不作为已验证发现。

## OpenAI Codex：实现理解、边界检查与调试

OpenAI Codex 用于理解 SQL/Python 数据路径、检查分母与时间窗口、定位测试或流水线问题，并核对 README、报告和指标产物是否一致。任何建议都要回到仓库代码和生成结果验证。

## Claude：长文本结构与表达

Claude 用于整理长文本的信息顺序、压缩重复表述和改善可读性。文字调整不得改变指标口径、扩大因果含义，或把代理指标改写成订单、收入等源数据不支持的事实。

## 人类责任

人类负责抽样方案、清洗规则、指标定义、代码执行、SQL 复核、业务判断和最终发布。是否保留模型建议由人类决定；公开数字、图表和解释由人类逐项签核。

## 典型纠偏

早期建议曾包含依赖价格或订单的 GMV、客单价和订单复购分析。源数据只有用户、商品、类目、行为与时间戳，没有价格、金额或订单 ID，因此这些建议被删除；重复购买只保留为购买事件和购买日代理。

另一个关键纠偏是：兴趣阶段覆盖与购买阶段覆盖是独立去重用户总量，二者差值不能当作“兴趣未购人群”。在提出人群实验前，必须先显式计算用户级交集 `engaged_without_buy`。

## 验证方法

1. 数字回查 `results/metrics.json` 和结果表；来源信息回查 `data/source_manifest.json`。
2. Pandas 结果用 SQLite/SQL 交叉核验，指标定义与分母集中记录。
3. 自动化测试检查核心数字、文档存在性、表述边界和公开仓库文件范围。
4. 最终发布前人工复读标题、图注、限制和建议，避免把相关性写成因果性。

## 原则：AI 不是事实来源

AI 不提供本项目的事实依据，也不替代原始数据、官方来源、可执行代码或人工责任。无法由这些证据追溯的内容，不进入公开结论。
